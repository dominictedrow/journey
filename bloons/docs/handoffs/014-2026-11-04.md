## Done
- New `bloons/hud.py` (portable): `parse_lives` / `parse_money` / `parse_round` / `parse_hud` → `Hud(lives, money, round, rounds_total)`, with None for any field that doesn't parse cleanly. Money must start with `$` and have well-formed commas. Round must be a valid `N/M` token, and junk tokens such as the OCR'd "ROUND" label are ignored. Digit confusables (O→0, l→1, S→5, …) are fixed only inside numeric-looking tokens. Hard bounds apply, and a box with two different candidates returns None.
- `HudFilter(confirm=2)`: holds the last accepted value per field. A change is accepted only after 2 identical consecutive reads, a None never overwrites a value, and `misses` counts unreadable frames. Call `reset()` on a new game.
- `platform_mac.py`: Vision call moved to module-level `ocr_image(cgimage)`. `Game.read_hud()` now returns a parsed `Hud`, and `Game.read_hud_raw()` keeps the raw strings.
- `scripts/make_crops.py` now also writes Vision's raw text into each `hud_*` crop as `"ocr"` in `crops.json`, so the parser is tested on real OCR output on Windows too.
- Tests: 10 pass (`tests/test_offline.py`). New ones: fixture parse vs `truth`, edge cases, filter behaviour, and `test_hud_ocr_live` (Mac only; runs Vision on the crops and prints a skip elsewhere).

## Decisions made
- Strict parsing (None over a guess): a missing value is cheap, a wrong number reaches the agent.
- One uniform rule for the filter (any change needs 2 matching reads) instead of per-field direction rules. Lives can go up (farms, abilities), money jumps on sells, and round drops on restart, so direction rules would be wrong some of the time. The cost is about one extra read (~70 ms) per change.

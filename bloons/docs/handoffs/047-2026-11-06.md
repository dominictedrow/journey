## Done
Four review → fix rounds on harness code only (no RL env/model/training touched). 115 offline tests pass (93 at session start), pyflakes clean. Nothing run live.
- **Button reads are debounced.** `_button_now(content, tries, first)` returns a value only once `tracker.confirm` consecutive reads agree. `start_round` presses Space only on agreeing reads (reads that never agree → `no_button`, a new way to get that reason). `_sync_round` trusts one read only if it matches `tracker.button` and `observe()` ran in the last `SYNC_FRESH_S` (1 s); `use_ability` / `use_ability_of` call it only for round-only abilities.
- **Money confirms (`_money_moved`)**: a move in [½·cost, ~1.1·cost] (refund: + `REFUND_INCOME_SLACK` $300) confirms on one read and is forced into the filter. Outside that, up to `max_move` (default 1.5×) and down to `min_move`, it needs two agreeing raw reads (`_hud_money(raw=True)`: a miss isn't a read). It returns the amount to book (0 = unconfirmed, then `_money_unsure` is set).
- **`_money_before`**: uses the filtered money if a read agreed with it in the last `MONEY_FRESH_S` (0.5 s) and nothing went unconfirmed since. Otherwise it takes raw reads that are *not* fed to the filter. Two agreeing reads below the filtered value count only when `_money_unsure` is set (money only drops when we spend), so a misread repeated on a still frame can't replace good money.
- **Hero level**: `buy_hero_level` confirms anywhere from $1 to the whole level's price (`guards.hero_level_price(s, xp_into_level=0)`), and books the measured amount in `hero.spent`. The XP estimate resets at each level-up, so a wrong estimate heals.
- **Hero XP**: credited at most once per round (`_xp_round`) and only to a hero that was placed at the previous `observe()` (`_hero_prev`). `place_hero` sets `_hero_prev` when the button shows a running round, so a hero placed mid-round earns that round.
- **Abilities**: upgrades keep abilities that carry over (Heli Redeploy at 0-5-0, Vine Crush, Take Aim) with their timer and slot. Cooldowns are per instance (`slot["cds"]`, `_cd(a, key)`); the slot-level `cooldown` is gone. `_gain_ability` only adds (no `replace`); `record_upgrade` owns the "later tier replaces earlier" rule.
- **RoundTracker**: `RoundState.ended_rounds` (tuple; `ended_round` is now a property = last). A HUD jump of ≤ `MAX_ROUND_JUMP` (5) ends every round in between; a bigger one only the last. If the HUD comes back inside a jump's range, the jump was a misread and those rounds can end again (`_jumped`). A stretch that starts while the HUD still shows a finished round is taken as the next round (`_running_round`). No HUD-drop "replay" rule: a Defeat Continue replays only the lost, unfinished round. `tracker.running_round` / `tracker.button` properties. `observe()` sets `rounds_done` mid-round from `running_round - 1`.
- `HudFilter._agree` → public `agrees()`. `harness._load` → public `load_data()`; `tools/play.py` uses it and turns a bad `--hero` into an argparse error.

## Decisions made
- Two-read confirmation for off-estimate money moves rather than hard caps: hero-level, sell and unshown table prices are estimates (review 2 showed caps break real buys/sells).
- Money-drop protection lives in `_money_before` (harness), not `HudFilter`: putting it in the filter broke its documented "accepted if it repeats" behaviour.
- Rollback of a misread HUD jump may re-fire `round_ended` for a round; XP is still deduplicated.

- The real fix for hero-level pricing is reading the price off the hero panel's level-up button (like `upgrade()` reads `read_paths`); needs a live screenshot for the `ui.json` crop.
- A false idle edge mid-round (passing the 2-frame confirm) still swallows that round's real end (indistinguishable with Auto Start off).
- Hero placed late in a round with no observe before its end, and placed at idle: no XP for a round end observe() hadn't seen (intended).

**Learning notes**
1. **Why freeze BatchNorm when fine-tuning on one knee per batch?** BN normalizes with the batch's mean/variance in
   training and with running averages in eval. With 15 windows from one knee, the batch statistics describe that one
   knee, not the data. Training then sees a different normalization than eval, and the running averages drift with
   whichever knees came last. Frozen BN keeps the ImageNet-pretrained statistics, which is the usual choice for
   small-batch detection and medical fine-tuning.
2. **Persistent workers and the epoch.** A DataLoader worker holds its own copy of the dataset, made when it starts.
   Calling `ds.set_epoch()` in the main process later doesn't reach it. The sampler, though, runs in the main process
   every epoch, so putting the epoch into the index (`epoch·n + i`) is a cheap way to tell long-lived workers which
   epoch it is.
3. **Why the OOM retry moved out of `except`.** While Python handles an exception, the traceback keeps every frame of
   the failed call alive, along with the activations those frames reference. `torch.cuda.empty_cache()` can only
   free memory that nothing references, so inside `except` it frees almost nothing.

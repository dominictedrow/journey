### Learning notes
1. **Profiling beats estimating, in both directions.** The roofline model was too pessimistic for Track A's convs (cuDNN
   on tensor cores beat the 50% efficiency assumption) and too optimistic for the ViTs (CUDA autocast runs LayerNorm in
   fp32, which roughly doubles its memory traffic). The ranking held, though: bandwidth-bound ops are the largest share.
2. **Why `torch.compile` wins here.** It doesn't make matmuls faster. It fuses the chains of cheap elementwise ops
   (cast → LayerNorm → cast, bias + GELU, residual adds) into single Triton kernels, so the activations cross memory
   once instead of 4–5 times. That's exactly the 50–70% of time the profile shows outside GEMMs.
3. **An "exact" optimization can still be slower.** Folding BN into a conv removes one pass in theory. But PyTorch's
   cuDNN path adds a conv bias as a separate broadcast kernel, which is slower than cuDNN's fused BN kernel. Always
   measure.
4. **Gradient checkpointing is a VRAM/time trade.** It throws away activations in the forward pass and recomputes them in
   backward: ~1 extra forward pass (−18 to −23% speed here) for 3× less memory. On a 16 GB T4 we can afford to turn it
   off at batch 1.

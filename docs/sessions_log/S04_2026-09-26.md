## Done

  - `prompt.py`: the reader's instructions and strict JSON schema. Per finding: `state` (present/absent/uncertain/
    not_mentioned), `severity` 0–3 on a finding-specific scale, `degenerative`, `postoperative`, a ≤12-word quote. Per
    study: language, knee side. It also holds the conventions from the brief and the bins → prior-probability map.
  - `reader.py`: Claude API over Message Batches (50% price). Features:
    - cached system prompt;
    - resumable raw-JSON store per study, keyed by prompt version;
    - `sync` smoke mode, `submit`/`collect`/`parse`/`cost`;
    - a budget guard that counts spend across all runs and refuses a full run that would break $50.
    Custom IDs are hashes (UIDs don't fit the API's ID pattern).
  - `public_sets.py`: downloads 4 readers + 3 references with the Kaggle CLI, records license + sha256 in a manifest,
    turns each set's own "silent" marker into NaN, and leak-checks against gold.
  - `blend.py`: probability-space consensus. Silent readers vote 0.5. It also sets the agreement × certainty weight
    (prvsiyan's public formula), fills Synovitis ← Effusion and PF OA ← Medial OA, and gives silent cells a low weight.
  - `calibrate.py`: per finding, bin → P(gold), shrunk toward the prior (5 pseudo-studies), isotonic over the bin
    order, **leave-one-out** for the gold rows.
  - `folds.py`: StratifiedGroupKFold. Groups = normalized report hash (union-find; site proxy merged in only in
    `group` mode). Gold is its own stratum; other studies are stratified on 4 binarized labels (+ site when available).
  - `build_labels.py`: writes `labels_<v>.parquet` (the train_sup format), `folds_<v>.csv`, `qa_<v>.json`,
    `disagreements_<v>.md` (with report text, so it stays in the cache) and `docs/labels.md` (numbers only).

## Surprises / notes
1. **My first silent-cell rule was wrong.** With silence = 0.2 and a known-only mean, blended Fracture (0.778) and
   Lateral OA (0.793) scored *below every single reader*. Reason: a single explicit negative among silent readers
   became a confident 0.05. Treating a silent reader as a 0.5 vote (each public set's own convention) fixed it:
   0.817 / 0.821. I saw both gold numbers before choosing. It's one global switch, recorded in E001, and `--silence
   skip` stays in the ablation table.
2. lixin writes 0 where the report is silent. It now counts only when it asserts a positive or when another reader
   spoke.
3. `site_mode="group"` can collapse the folds: a duplicated report shared by two sites chains the sites together. The
   code refuses when fewer than 2×folds groups remain. Dom chose `stratify` anyway (decision 2026-09-26).
4. Batches don't accept the server-side refusal `fallbacks` parameter. A refused study is saved as an error and
   resubmitted by the next `submit`.

Design choices to check:
- **The reader outputs categories, code turns them into numbers.** The gold 58 only set the value of each category,
  with heavy shrinkage.
- **Silence = "don't know"** (0.5 vote, low training weight), never a hard negative.
- **Gold rows keep report labels** in the parquet. Whether to also train on gold (cross-fitted, 2–3× weight) is left to S05.
- **Labels/folds files stay out of the repo** (`*.parquet` is gitignored; MIRA-derived). `docs/labels.md` holds numbers only.

Learning notes:
1. **Soft vs hard labels.** A report saying "small effusion" isn't a clean yes or no for an annotator whose threshold
   is "moderate or more". Training on a hard 1 tells the model it's certain; training on 0.4 with weight 0.6 tells it
   "lean negative, not sure". With BCE, a soft target moves the optimum logit to log(p/(1−p)) instead of ±∞. That
   keeps the model from over-fitting to label noise, and the per-cell weight lets confident, agreed labels dominate
   the gradient.
2. **Why grouped folds.** 223 studies share a report text with another study. If one copy trains and the other
   validates, the model has effectively seen the validation label, and CV looks better than the test will be.
   Grouping by a normalized hash puts all copies in one fold. The same logic applies to anything that ties studies
   together: patients, sites and scanners.
3. **Why the gold CI is so wide.** AUC for one finding compares every positive with every negative. MCL has 9
   positives, so its AUC rests on 9 × 49 pairs, and moving one positive's rank shifts it by several points. The
   bootstrap resamples the 58 studies with replacement 1,000 times. The spread of the macro AUC across resamples is
   ±0.04, so a 0.01 "gain" on gold is noise. That's why gold decides directions, never per-finding knobs.
4. **Blending decorrelated readers.** Two readers with the same errors add nothing. Two that err on different reports
   average their mistakes away. Leave-one-reader-out shows no single public reader is essential here (0.888–0.890 vs
   0.889). That's why our own Claude reader, with a different prompt, is the ingredient most likely to move the blend.

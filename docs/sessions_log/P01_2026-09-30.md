## Review guide for Dom
- **Start with `tests/test_perf.py`.** Every change has a test showing the output is unchanged: the new rank loss is checked
  against the old loop (values and gradients), threaded reads against serial reads, and folded models against unfolded ones.
- **`train/common.py`**: `resolve_precision`, `make_scaler`, `GpuMeter`. Check the fp16 stop rule in the trainers'
  `check_finite`: bf16 stops on any non-finite loss (as before, but detected up to `log_every` steps later, and always
  before a checkpoint is written); fp16 tolerates isolated bad micro-batches because the scaler skips those steps.
- **`model/fuse.py`**: the two folding formulas are in the docstring. Only BNs that directly follow a conv are folded.
- **Behaviour changes to be aware of:** (1) with `windows_per_read > 1` the MAE centres are stratified per read and a batch
  holds fewer distinct series (a knob; 1 = the old behaviour); (2) the cache builder now holds a series' raw bytes in RAM
  until each slice is decoded (≈15 MB for a typical series, ≈150 MB for the largest), instead of re-opening files.

### Learning notes
1. **Roofline.** A kernel is compute-bound if it does more FLOPs per byte moved than the GPU's ratio (peak FLOP/s ÷
   bandwidth ≈ 200 on the T4). A matmul with large dimensions does hundreds of FLOPs per byte, but a LayerNorm or GELU does ~1.
   Transformers spend a surprising share of time in those cheap-looking ops, which is why "fusing" (doing several of them
   in one pass over memory) is the main trick behind `torch.compile` and FlashAttention.
2. **Why fp16 needs a loss scaler and bf16 doesn't.** Both have 16 bits. bf16 keeps fp32's 8 exponent bits (same range,
   less precision); fp16 has 5 (range ~6e-8 to 65504). Small gradients underflow to zero in fp16, so the loss is
   multiplied by e.g. 65536 before backward and the gradients divided afterwards. If anything overflows, that step is
   skipped and the factor halved.
3. **Host syncs.** CUDA runs asynchronously: Python queues kernels and moves on. Anything that needs a GPU value on the CPU
   (`.item()`, `if tensor.any()`, boolean indexing with a data-dependent size) makes Python wait until the GPU has caught
   up, so it can't queue ahead. Here that cost is small but free to remove.
4. **Folding.** In eval mode BatchNorm and LayerScale are fixed per-channel multiply-adds, and a multiply-add right after
   a linear layer can be absorbed into that layer's weights. Same math, one less pass over the activations.

## Why
A CPU-only code review of the never-GPU-run perf changes (fp16, compile buckets, effective_batch, multi-GPU) found six

## What was done
Two commits, so each explains one thing:
1. **Earlier three fixes** (already coded, now committed): RankBank NaN rows in fp16, gradients leaking across epochs,
   silent no-training when an epoch has fewer batches than `accum`. Plus `tests/test_overfit_sup.py`.
2. **bug.md fixes 1–3:**
   - **Run identity guard** (`train_sup.check_run_identity`): before anything is written, the run dir's recorded
     config (`config.yaml`, else `last.pt["cfg"]`, so old checkpoints are covered) must match `folds.fold`,
     `folds.file` (same file under another spelling is fine: `os.path.samefile`) and `run_name`, or `SystemExit`.
     `labels` / `model` differences only warn; `optim.epochs` etc. may change on resume.
   - **multi_fold run dirs**: an explicit `run_dir` X is the run root; fold k runs in `X/fold<k>` (passed to the child
     as `--set run_dir=...`), logs in `X/multi_fold/`. Then `len(set(run_dirs)) == len(folds)` is checked.
     *Deviation from the plan:* the plan rewrote X only when two or more folds shared it. I apply it whenever
     `run_dir` is explicit, even for one fold, so `--folds 0` followed later by `--folds 0 1` keeps fold 0 in the same
     dir instead of moving it from X to X/fold0 (which would silently restart it).
   - **Skip finished folds**: `metrics.json` now records `epochs` and `run_name`. `multi_fold.is_finished` = same
     fold and `epochs >= optim.epochs` (no `epochs` key = old format = finished). Only pending folds are launched;
     loader workers are split over `len(pending)`; nothing pending → exit 0 without spawning. `--rerun-finished`
     re-launches them. `run_folds` unlinks a fold's stale STOP just before launching it.
   - **fp32 eval retry**: `train_sup.predict` checks the batch on the CPU array it already copies; a non-finite batch
     (or a `RuntimeError` in reduced precision) is re-run with autocast off, under
     `torch.compiler.set_stance("force_eager")` so the compiled encoder doesn't recompile per bucket (falls back to a
     plain call on torch < 2.6). `predict` now returns `(uids, probs, stats)`.
   - **evaluate**: records `val_n_retried_fp32` and `val_n_nonfinite`; if any study is still non-finite,
     `val_macro_auc = NaN` (top-k ranks it last) and `val_macro_auc_finite` keeps the subset AUC. **Pending Dom.**
   - **metrics**: `per_finding_auc` / `macro_auc` / `bootstrap_macro_auc` / `auc_table` take
     `nonfinite_pred="warn"|"ignore"|"raise"` (default warn, one warning per call, NaN labels stay silent). Bootstrap
     replicates use "ignore" (one warning on the full set). Caller audit: `ssl/probe.py` passes "ignore" (a finding
     without a probe is an all-NaN column); `labels/build_labels.py` needs nothing (`reader_for_scoring` fills NaN
     with 0.5, so a NaN there would be a real bug worth the warning); `labels/public_sets.py` already `nan_to_num`s.
3. **Notes item:** `tests/test_compiled.py::test_half_trackA_runs_and_matches_fp32` (pure fp16, resnet10t for
   BatchNorm and `coatnet_rmlp_nano_rw_224` for the real backbone's block types). ~1 s each.

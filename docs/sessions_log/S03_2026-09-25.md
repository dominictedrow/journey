  weights (1e-5); masked keys get exactly 0 weight; loss at init = ln 2 for all 3 heads; padded windows don't change the

Design choices to check (mine, not yours; each is a flag in the config):
- **GroupNorm in the conv stem, not the paper's BatchNorm.** Our micro-batches are 1–2 studies, and MAE feeds
  75%-blanked images, so batch statistics would differ between pretraining, fine-tuning and eval. `stem_norm: bn` is the ablation.
- **Blanking masked pixels before the conv stem** (the leak check above). Without it, MAE can cheat through the
  stem's overlapping receptive fields.
- **`AttnMILHead` defaults to Raptor exactly (tanh, not gated).** The brief said "gated"; `gated: true` is one flag.
- **Rank loss with a memory bank.** At batch 1–2 a batch almost never contains a positive/negative pair for a finding,
  so the current studies are ranked against the detached logits of the last 256 studies. `rank_bank: 0` disables it.
- **Slice-position Linear is zero-initialized**, so fine-tuning starts from the MAE features unchanged.
- **Input normalization** `(x/255 − 0.5)/0.5` for Track B (UNVERIFIED that the corpus mean is near 0.5; the GroupNorm
  stem makes it matter little). Track A uses ImageNet mean/std, like the public CoAtNet.
- **Model selection uses report-label val AUC only.** Gold-58 is computed and logged but never picks epochs (master plan §6).
- Track A config: 3 windows/slot in training (15/study) and 12/slot at eval (60), batch 1 × accum 24, backbone LR 3e-5,
  head 1e-3 (the public values, scaled to 12 GB). `slot_embed: true` is our small addition (zero-init).

Learning notes:
1. **Why pre-norm.** In a pre-norm block the residual stream `x` passes through every block untouched
   (`x = x + f(LN(x))`), so the gradient of the loss reaches block 1 through a clean chain of identity additions. In
   post-norm (`x = LN(x + f(x))`, the 2017 Transformer), every block's LayerNorm rescales the gradient on the way down.
   Deep post-norm stacks need careful warmup or they diverge. LayerScale goes further: each branch starts multiplied by
   0.1, so a 12-block network begins close to the identity function and "turns blocks on" as it learns.
2. **Why a conv stem helps a small-data ViT.** A patchify layer is one 16×16 linear map applied to non-overlapping
   patches. It has to learn edges, textures and their positions within the patch all at once, and its optimization is
   notoriously touchy (Xiao et al. 2021). A stack of 3×3 convs builds the same 16×16 token from overlapping local
   features, which brings back the locality prior CNNs have. That's worth the most exactly when data is scarce (4.4k
   studies) and training from scratch.
3. **How MAE's asymmetric encoder makes pretraining cheap.** The encoder only processes the 25% visible tokens (64 of
   256), and attention cost grows with tokens², so each encoder block is ~16× cheaper in attention and 4× cheaper in the
   MLP. The decoder that sees all 256 positions is deliberately small (4 narrow blocks) and is thrown away afterwards. To
   fill in 75% of a knee slice from scattered patches, the encoder must learn anatomy (where the menisci sit relative to
   the femoral condyles, what fluid looks like), and that's what fine-tuning reuses.
4. **The finding-query head as "12 learned questions".** Each of the 12 query vectors is a learned question ("is there
   an ACL tear?"). In cross-attention the question is the query, every window token offers a key ("here's what I
   contain") and a value ("here's my evidence"). The softmax over windows says which windows answer this question, so
   the ACL query learns to look at sagittal windows near the notch without being told. `return_attn=True` gives those
   weights for the attention-map plots in S07.
